# 첫 Lab 조회 실패의 유한 진단

실시간 Lab 조회가 실패했을 때 안전한 분류를 표시하고, 유효한 게시 기록으로 fallback하는 동작을 로컬에서 확인했습니다. 공개 배포·공개 화면 반영은 아직 확인하지 않았습니다. 앞선 공개 첫 조회가 과거 게시 기록으로 fallback했다가 수동 조회 뒤 회복한 원인은 **UNOBSERVED**로 유지합니다.

## 변경 범위

[API 조회](../../../apps/lab-web/src/lib/api.ts)는 HTTP 응답 오류, JSON·DTO·요청 실행 ID 불일치, 요청 중단, 원인을 확인하지 못한 전송 실패, 기타 실패를 구분합니다. 화면에 전달하는 진단은 유한한 `kind`와 검증한 HTTP 상태 숫자 또는 `null`뿐입니다. 원문 URL·응답 본문·헤더·예외 message·cause·stack은 표시하지 않습니다.

`REQUEST_ABORTED`는 요청 중단이며 timeout의 증명이 아닙니다. native `TypeError`도 CORS 원인의 증명이 아닙니다. 먼저 확인한 HTTP·JSON·DTO 실패는 이후 signal 중단으로 덮어쓰지 않습니다. 정상 빈 목록과 설정 거부를 네트워크 장애로 분류하지 않으며 기존 한국어 오류 문구를 유지합니다.

[소스 선택](../../../apps/lab-web/src/lib/observation.ts)은 기존 live → 최신 유효 게시 기록 → 합성 샘플 순서를 유지합니다. 캐시·원래 수집 시각·관측 파일404 처리·기존 취소 시한·자동 재시도 없음도 유지합니다. 성공한 live 조회의 `liveFailure`는 `null`입니다. 진단은 이번 병렬 조회에서 먼저 관측한 실패 정보이며 시스템 전체의 근본 원인을 뜻하지 않습니다.

## 실제 로컬 검증

| 검증 | 결과 |
| --- | --- |
| 기존 production + 새 observation 검사만 적용한 RED | 16개 중3개 통과·13개 실패·skip0, exit1. `liveFailure`가 없는 기존 동작을 검출했습니다. 실패 수에는 부모 그룹 실패도 포함됩니다. |
| 후보 production3개와 테스트2개를 적용한 전체 웹 GREEN | 223개 모두 통과·실패0·skip0, exit0 |
| Astro 검사 | 47파일·오류/경고/힌트0 |
| 프로젝트 base 빌드 | 두 페이지 빌드 성공 |

[API 회귀검사](../../../apps/lab-web/tests/api.test.ts)는 실제 localhost HTTP429/500·canary 본문, 잘못된 JSON·DTO·요청 ID, 요청 중단과 연결 종료를 다룹니다. 기존 redirect의 `TypeError` 거부·대상 요청0회도 유지합니다. [fallback 회귀검사](../../../apps/lab-web/tests/observation.test.ts)는 유효한 이전 기록의 전체 값과 시각 보존, 다음 live 성공의 진단 해제를 확인합니다. 이 검사는 공개 HTTPS 장애를 재현한 결과가 아닙니다.

로컬 프로젝트 base preview에서는 HTTP404의 고정 진단과 10월11일 게시 기록의 소스·원래 시각 보존, 선택한 합성 실행의12/7/3/2/0을 확인했습니다. 데스크톱은 client/scroll 폭1265px, 모바일은375px로 같았습니다. 데스크톱 스크린샷에서 안내문을 확인했으며 모바일 스크린샷은 해당 안내문 위치가 아니므로 줄바꿈의 시각 검증 근거로 사용하지 않습니다.

첫 로컬 preview는 project base 환경 누락으로 hydration이 실패했고 올바른 base를 적용한 뒤 위 확인을 완료했습니다. 이 로컬 설정 문제를 앞선 공개 fallback의 원인으로 소급하지 않습니다.

## 남은 범위

다음은 공개 반영과 실제 첫 조회의 실패 정보 관측입니다. 이번 변경으로 공개 장애 원인을 확인하거나 해결했다고 표시하지 않습니다. 새 자동 재시도·프록시·보안 설정·서버·SQL·토큰 변경은 없습니다. 기동 복원·토큰 교체·자원 예산 정책·PR102 접수 gate의 네 보류도 유지합니다.
