# 근거 검색의 초기 입력 보호

2026-10-21 KST, 별도 서버·새 토큰 없이 기존 웹과 로컬 브라우저에서 확인했습니다.

## 관찰한 문제와 수정

공개 근거 목록의 첫 접속 직후 `Error`·Java·CI를 입력했을 때 native input/select의 값은 바뀌었지만 목록은 기본6개로 남았습니다. 이후 준비가 끝난 화면에서 조건 초기화 후 같은 입력을 하면1개로 바뀌었습니다. 실제 입력과 hydration의 선후 시점을 직접 계측하지 않았으므로 특정 네트워크 지연을 원인으로 확정하지 않습니다.

기존 SSR은 React 이벤트 연결 전에 검색 컨트롤을 활성 상태로 출력했습니다. 서버 렌더와 첫 클라이언트 렌더를 동일한 준비 전 상태로 두고, mount effect 뒤 검색어·기술·검증 환경·초기화·더 보기의5개 native 컨트롤을 활성화합니다. 준비 전에는 `aria-busy=true`와 “검색 준비 중…”을 표시합니다.

검색·필터·페이지 계산과 공개 데이터·API·스타일은 바꾸지 않았습니다. 근거 카드와 링크는 준비 전에도 남습니다. 준비 후 마지막 더 보기 버튼은 기존대로 native enabled·`aria-disabled=true`를 유지하여 초점을 잃지 않고 후속 Tab 이동을 할 수 있습니다.

## 로컬 확인

- 기존 웹207개 검사 통과·skip0, Astro47파일 오류·경고·힌트0, 프로젝트 경로 빌드 성공.
- 빌드 HTML에서 script 요소만 제거한 임시 사본에서 `aria-busy=true`,5개 native disabled, 준비 중 placeholder, 카드6개·링크15개를 실제 DOM으로 확인했습니다. 이는 스크립트 실행 전 SSR 상태의 사본이며 실제 느린 통신의 전환 시간을 측정한 시험은 아닙니다.
- 실제 앱에서는 mount 뒤5개 컨트롤이 활성화되고 `aria-busy=false`·원 placeholder로 바뀌었습니다. Error+Java+CI 결과1개, 초기화 뒤19개 중6개, 더 보기6→12→18→19개를 확인했습니다. 마지막 버튼은 native enabled·aria-disabled·초점 보존, 실제 Tab 뒤 다음 실시간 조회 버튼으로 이동했습니다.
- 1280px 문서 폭1265px,390px 문서 폭375px로 가로 넘침이 없었습니다. 모바일에서 검색어→기술→검증 환경→초기화의 실제 Tab 순서, 본문17px·근거 링크 높이44px를 확인했습니다.
