# GitHub App 토큰 자연 만료 후 Jenkins 갱신

README·공개 카드·Pages와 별도 컨테이너 검증의 상태는 [공개 반영 근거](PUBLICATION.md)를 따릅니다.

2026-10-23 **19:19:30(KST)**에 Jenkins의 기본 자격증명 저장소에 있는 App credential을 사용해, 실제 만료한 토큰의 거부와 native 갱신 후 인증 성공을 한 주기 확인했습니다. 공개 기록은 [제한된 요약 JSON](natural-expiry-summary.json)이며, 토큰·개인키·관리 응답·캐시 원문·접속 정보는 포함하지 않습니다.

## 실제 관측 순서

| 단계 | 2026-10-23 KST | UTC | 확인한 결과 |
| --- | --- | --- | --- |
| 기존 토큰 자연 만료 | 19:18:35 | 10:18:35 | 시계·캐시를 변경하지 않고 실제 만료를 기다림 |
| 만료한 토큰으로 저장소 GET | 19:19:28 | 10:19:28 | GitHub 응답 **401**, 응답 시각이 기존 만료 뒤임을 확인 |
| Jenkins native 자격증명 접근 | 두 GET 사이 | 두 GET 사이 | `getPassword()` **1회**로 lazy refresh |
| 새 토큰으로 저장소 GET | 19:19:30 | 10:19:30 | **200**, 설치 대상으로 의도한 저장소 한 개와 일치 |
| 새 토큰 만료 | 20:19:30 | 11:19:30 | 새 응답 시각부터 **3,600초** 유효 |

갱신 뒤 토큰과 캐시 객체가 기존 것과 달라졌음을 서버 메모리에서 비교했습니다. 기본 저장소의 credential 소속, Jenkins job 구성·상태, 비밀 입력 파일은 전후가 같았습니다. 토큰·키의 값이나 접두어·비밀 해시를 출력하거나 저장하지 않았습니다.

## 검증 조건과 한계

- 고정한 기존 캐시의 실제 만료 뒤 401을 확인한 경우에만 native 접근을 한 번 수행했습니다. 만료 전 토큰을 새로 발급하거나 캐시를 비우고 성공으로 처리하지 않았습니다.
- 새 인증은 HTTP 200만 보지 않고 저장소 개수·신원과 응답 시각·새 만료 시각을 함께 검사했습니다. 실패하거나 응답이 불명확한 POST를 자동 재시도하지 않았습니다.
- 자격증명 변경·커밋 상태 쓰기·빌드·배포·서비스 재시작은 하지 않았습니다. 이번 갱신 뒤 새 전체 CI 실행을 증명하는 기록이 아닙니다. 이전 build 151의 [App 상태 쓰기 검증](README.md)은 별도 결과입니다.
- 확인한 범위는 **기본 저장소 credential 접근 시의 lazy refresh 한 주기**입니다. 모든 빌드 바인딩의 캐시, 접근 없는 선제·주기 갱신, 개인키 교체, 권한 철회 뒤 복구, 장기간 연속 운영은 검증하지 않았습니다.
- 앞선 첫 시도는 검증 응답 처리가 불완전해 **UNVERIFIED**로 남겼습니다. 캐시 만료 시각이 바뀐 관측만으로 그 시도를 성공으로 소급하지 않았습니다. 위 표는 별도로 완료한 후속 실행의 결과입니다.

한 번의 실제 만료 검증이 완료되어 일회성 후속 예약은 종료했습니다. 정기 토큰 발급 작업을 추가하지 않았습니다. Pages 토큰 교체·별도 환경의 K3s/Jenkins 기동 복원·자원 예산 정책·PR #102는 보류합니다. 재개와 판단 기준은 [Jenkins 운영 안내](../../runbooks/jenkins-ci.md#자연-만료-후-갱신-확인--2026-10-23-kst)를 따릅니다.
