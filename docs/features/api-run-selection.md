# API 안내에서 실행 선택

[실행 한 건 조회](https://devdooly.github.io/devdooly-platform-lab/api-guide/#api-detail) · [현재 기능과 보류](../AUTONOMOUS_WORK.md)

JSON 목록에서 ID를 찾아 복사하던 과정을 줄입니다. API 안내의 실행 상세 항목에서 목록을 불러오고, 정확한 ID와 입력 건수를 보고 실행을 선택할 수 있습니다.

## 이용 순서

1. **실행 목록 불러오기**를 누릅니다. 위쪽 실행 목록 항목에서 직접 GET한 응답도 같은 선택 목록에 반영합니다.
2. **조회한 실행 목록에서 선택**으로 ID를 고릅니다. 같은 이름의 실행도 ID와 입력 건수로 구분합니다. 선택만 하면 상세 요청을 보내지 않습니다.
3. **GET으로 직접 조회**를 눌러 선택한 ID의 실제 JSON·HTTP 상태·요청 경로와 수신/관측 시각을 확인합니다.

목록은 최근 최대 20개입니다. 유효한 빈 목록이나 목록에 없는 ID는 존재하지 않는 실행을 뜻하지 않으며, **경로 파라미터 · 실행 ID**에 직접 입력할 수 있습니다. 목록을 다시 읽어도 현재 ID를 첫 항목으로 덮어쓰지 않습니다.

## 선택과 응답 구분

실행 A의 응답을 받은 뒤 B를 선택하기만 하면 아래 응답은 여전히 A입니다. 안내문으로 이 차이를 알리고 기존 요청 경로·JSON·시각을 그대로 표시합니다. JSON 복사도 표시 중인 응답을 사용합니다. B의 GET을 직접 요청한 뒤에만 그 요청의 로딩·응답·오류로 전환합니다.

목록 조회가 실패하거나 선택에 사용할 구조를 확인하지 못하면 이전에 검증한 선택 목록과 원 시각을 보존하고 이번 실패를 구분합니다. 유효한 빈 목록은 새 빈 목록으로 반영합니다. JSON 응답 자체를 살펴보는 API 도구이므로 HTTP/JSON 수신 결과와 선택 목록의 DTO 검증은 별개입니다. 잘못된 선택 구조를 정상 옵션으로 만들지 않으며, 원래 JSON을 다른 응답으로 바꾸지도 않습니다.

## 범위와 검증

기존 `GET /demo/runs`와 `GET /demo/runs/{id}`를 재사용합니다. 자동 상세 조회·새 endpoint·POST·실행 생성·스냅샷 대체는 없으며 기존 8초·256 KiB 응답 제한과 입력 준비/요청 중 잠금을 유지합니다.

`lib/api-run-choices.ts`의 독립 테스트는 같은 이름의 다른 ID·순서, 유효한 빈 목록, 잘못된 DTO·ID·시각·중복 ID·JSON을 확인합니다. 기존 서버 렌더링 검사는 새 선택 입력도 준비 전에 잠겼는지 확인합니다. 전체 웹 검사·타입·빌드와 이번 기능의 실제 브라우저·같은 main CI/Pages·공개 결과는 변경 PR에 기록하며, 이전 기능의 검사를 새로 수행한 것으로 표시하지 않습니다.

2026-10-24 후보 검증은 웹 293개 통과(실패·생략 0), Astro 62파일 진단 0, 프로젝트 경로 4페이지 빌드입니다. 별도 독립 리뷰에서 목록 정체성·수동 조회·이전 응답 구분과 helper의 8개 시나리오를 확인했습니다. 로컬 개발 서버는 시작을 보고했지만 7791·7790에서 `503 no available server`를 반환해 로컬 조작 검증을 완료하지 못했습니다. 원인은 확정하지 않았으며, 이 실패를 타입/빌드 성공이나 공개 브라우저 검증으로 대신하지 않습니다. 공개 직접 이용 결과는 해당 PR에 별도로 기록합니다.
