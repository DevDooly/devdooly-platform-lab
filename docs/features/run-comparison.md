# 두 실행 결과 비교

[비교 화면](https://devdooly.github.io/devdooly-platform-lab/runs/compare/) · [서비스 목차](https://devdooly.github.io/devdooly-platform-lab/#services) · [다음 기능과 보류](../AUTONOMOUS_WORK.md)

단일 실행 화면을 오가며 계산하던 차이를 한 화면에서 확인합니다. 이 기능은 기존 공개 API에서 저장된 실행을 읽습니다. 실행 생성·DB 수정·운영 배포를 수행하지 않습니다.

## 사용 순서

1. **실행 목록 조회**를 눌러 최근 최대 20개 실행을 읽습니다. 페이지를 열기만 하면 API를 호출하지 않습니다.
2. A와 B에 서로 다른 실행을 고릅니다. 목록보다 오래된 실행도 유효한 ID를 직접 입력할 수 있습니다.
3. **두 실행 비교**를 누르면 A·B 상세를 순서대로 읽고 두 응답을 모두 확인했을 때 비교를 표시합니다.
4. 건수, 입력 대비 성공·실패 비율, 조회된 실패 이벤트의 사유별 차이를 봅니다. 차이의 방향은 항상 **B − A**입니다.
5. **비교 링크 복사** 또는 **비교 요약 CSV 다운로드**로 표시 중인 두 실행을 공유합니다. 선택만 바꾸었을 때는 직전 결과임을 표시하며 공유·CSV도 그 표시 결과를 사용합니다.

링크에는 실행 ID 두 개만 담습니다. 링크를 열면 선택을 복원하며, 비교 버튼을 눌러야 다시 조회합니다. 링크는 특정 시점의 결과를 고정한 artifact가 아닙니다. CSV는 현재 표시한 요약·실패 사유·출처와 원기록/조회 시각을 포함하고, 한글 UTF-8 BOM과 수식으로 해석될 수 있는 문자열의 이스케이프를 적용합니다.

## 비교의 의미와 한계

- **건수:** 입력·성공·실패·중복·대기. 서로 다른 입력량이면 원시 건수만으로 품질을 비교하지 않습니다.
- **비율:** 각 실행의 입력 건수를 분모로 사용합니다. 차이 단위는 퍼센트포인트(%p)이며 입력 0건의 비율은 산정하지 않습니다.
- **실패 사유:** `outcomes` 중 `FAILED`만 집계합니다. 중복 이벤트의 사유는 실패 사유에 포함하지 않습니다. 조회된 실패 이벤트 수와 보고된 실패 건수가 다르면 부분 관측임을 경고합니다.
- **시각:** 실행 시작/완료, API 관측, 브라우저 수신을 구분합니다. 두 GET은 동일 시점의 원자적 관측이 아닙니다.
- **인과:** 시나리오·seed·입력량 차이를 표시합니다. DTO에는 실행별 코드 버전이 없으므로 같은 버전의 실험이나 수정 효과·성능 향상을 증명하지 않습니다.
- **오류:** 요청마다 기존 8초·256 KiB 제한을 적용하며 자동 재시도·스냅샷 대체를 하지 않습니다. 한쪽 실패는 0건 실행으로 표시하지 않고, 직전 정상 비교가 있다면 원 ID·시각과 함께 보존합니다.

## 구현과 검증

구현은 `apps/lab-web/src/pages/runs/compare.astro`, `RunComparison.tsx`, `lib/run-comparison.ts`입니다. 계산·실패 이벤트 집계·0 분모·CSV·공유 URL의 독립 예상값을 `tests/run-comparison.test.ts`로 검증합니다. 전체 웹 검사·빌드, 새 화면의 실제 조작과 공개 전달 결과는 이번 변경의 PR에 기록합니다. 완료하지 않은 배포·브라우저 검증을 이 문서로 대신하지 않습니다.

2026-10-24 로컬 검증에서 웹 290개(실패·생략 0), Astro 61파일 진단 0과 프로젝트 경로 4페이지 빌드를 통과했습니다. 개발 프록시를 통한 실제 저장 실행 `synthetic-v1-seed-42` → `lab-fixture-20261015-v2-deploy`는 입력 12→1,000, 성공 7→500, 실패 3→300, 중복 2→200, 대기 0→0과 실패 사유 3종 각각 1→100을 표시했습니다. 역순 공유 선택 복원·Enter 비교, 한쪽 404 시 원래 두 ID·결과 보존, 모바일 실제 폭 375px의 가로 넘침 부재를 확인했습니다. 브라우저에서 내려받은 CSV 2,359바이트·29행의 BOM·숫자·사유·출처·시각도 별도로 대조했습니다.

첫 로컬 미리보기의 외부 API 직접 조회는 네트워크/CORS 유한 실패였고, 기본 sandbox의 개발 프록시는 네트워크 EACCES에 따른 502였습니다. 이후 네트워크가 허용된 개발 프록시의 GET으로 위 기능을 확인했습니다. 이 로컬 결과는 Pages의 직접 연결 확인과 구분하며, 원래 실패를 성공으로 바꾸어 기록하지 않습니다.

Pages 토큰 교체·별도 K3s/Jenkins 기동 복원·예산 정책·PR #102는 계속 보류합니다. 운영 API·worker·web 이미지/source pin, 기존 서비스와 자료는 변경하지 않습니다.
