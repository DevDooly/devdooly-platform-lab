# 현재 조건의 파일 비교 보고서 저장

[저장한 이벤트 JSON 비교](https://devdooly.github.io/devdooly-platform-lab/runs/offline/)에서 찾은 차이를 다시 검토할 수 있도록 별도 JSON 보고서를 내려받습니다. 두 파일 검증을 모두 마친 뒤 **비교 보고서 JSON 저장**을 누릅니다. 파일 선택 중인 초안이나 검증에 실패한 새 파일이 아니라 화면에 표시 중인 마지막 정상 비교를 사용합니다.

보고서는 현재 검색·분류에 맞는 **모든 sequence 그룹**을 담습니다. 화면에서 처음20개만 보여도 그 뒤의 일치 그룹을 함께 저장하며, 대응이 모호한 위치의 양쪽 후보도 생략하지 않습니다. 조건 일치가0개여도 원파일 메타데이터·현재 조건·건수를 가진 빈 보고서를 만들 수 있습니다. 새 파일 비교나 검색·분류·표시 한도를 바꾸면 이전 다운로드 안내를 현재 결과의 안내로 유지하지 않습니다.

다운로드 요청 시의 브라우저 메모리 snapshot을 파일로 만듭니다. 서버 업로드·추가 API 조회·브라우저 저장소 보관을 하지 않습니다. 화면의 성공 안내는 다운로드 요청을 뜻하며 실제 디스크 저장 완료를 확인한 메시지가 아닙니다. 보고서에는 파일 이름·출처·조건과 이벤트 원문이 포함되므로 외부에 공유할 때 내용을 확인합니다.

## 파일 형식과 범위

파일 이름은 `devdooly-event-comparison-report.json`입니다. 원파일의 runId나 파일 이름을 다운로드 경로로 쓰지 않습니다. 이 형식은 **검토 보고서**이며 [기존 이벤트 내보내기](event-export.md)의 schemaVersion1·2와 다릅니다. [파일 비교 입력](offline-event-comparison.md)에 다시 넣거나 세션을 복원하는 기능은 제공하지 않습니다.

| 필드 | 담는 내용 |
| --- | --- |
| `format`, `schemaVersion` | `devdooly-offline-event-comparison-report`, 보고서 버전1 |
| `capturedAt` | 보고서 생성 요청 시각. 파일 안의 과거 관측·내보내기 시각을 대체하지 않음 |
| `files.left`, `files.right` | 각 정상 파일의 name·byteLength·schemaVersion·원source·원filters·세counts·실제저장행수 storedOutcomeCount |
| `view` | 현재 화면의 원문 query·kind·displayLimit. 파일 안의 원래 검색 조건과 분리 |
| `counts` | 전체 sequence 그룹 totalGroups·현재조건 일치 matchingGroups·화면 표시 displayedGroups |
| `classifications` | 전체 비교의 다섯 분류별 그룹 수. 현재 필터 이후 집계로 바꾸지 않음 |
| `groups` | 현재 조건에 맞는 전체 sequence 그룹의 분류·입력/판정 차이 필드·양쪽 모든 원문 후보 |

그룹은 sequence 숫자 오름차순이며 같은 위치의 후보는 각 파일의 원래 순서를 지킵니다. 중복 eventId를 합치거나 모호한 후보 하나를 임의로 고르지 않습니다. 미관측·모호한 위치의 차이 필드는 비교하지 않은 `null`이며, 비교 후 차이가 없는 빈 배열과 구분합니다. 검색은 기존의 앞뒤 공백·대소문자 무시 규칙을 쓰되 보고서의 query 문자열은 사용자가 입력한 그대로입니다.

원source의 mode·시각은 파일의 자체 주장입니다. 파일 진위·현재 live API·전체 입력 완전성·같은 원본/실행 코드·회귀 원인을 인증하지 않습니다. 세counts가 같아도 전체 원본의 증거는 아닙니다. JSON은 문자열과 null을 보존하지만 원파일 bytes·숫자 표기·공백을 복원하지 않으며, native JSON 직렬화에서 `-0`은 `0`으로 기록됩니다. null로 직렬화되기 전 NaN·Infinity 등을 복원하지 않습니다.

## 검증 상태

로컬 최종 기본 병렬 웹 **505개**, Astro **86파일 진단0**, **5페이지 빌드**를 통과했습니다. 모델 targeted 첫9개·UI 첫18개 통과 뒤 독립 검토에서 이전 저장 함수가 남았을 때 읽기 잠금을 다시 확인하지 않는 경계를 찾았습니다. 부모의 현재 마운트·준비·읽기 잠금을 저장 직전에 확인하도록 보완하고, 오래된 저장 함수를 보유한 채 잠금만 바꾸는 반례를 포함한 UI V2 첫19개와 최종 검사를 통과했습니다. 실제 브라우저 경합을 관측한 기록은 아니며 최초504개·타입·빌드와 원 검토 기록을 보존합니다. 별도 독립 모델20사례와 UI V2 변경 범위도 확인했습니다.

로컬 실제 다운로드 파일을 읽어 화면20개와 별개로25그룹을 담은18,221bytes 보고서, 모호 분류·원문 검색 조건의1그룹2,544bytes 보고서, 일치0그룹1,642bytes 보고서를 확인했습니다. 원파일 메타데이터·v1 센서 필드 부재·v2 정확 조건·nullable 원시각과 생성시각을 분리했고, 모호한 sequence9의 A후보2개·B후보1개를 모두 담았습니다. 잘못된 새 A파일 검증 후에도 원래 정상 파일과 현재 조건으로 보고서를 만들며, 조건 변경 시 이전 요청 안내를 지웠습니다. 요청은 키보드 Enter로도 확인했습니다. 다운로드 결과의 파일 존재·내용 확인과 화면의 ‘요청’ 안내를 구분합니다.

375px에서 전역 가로 넘침0·본문17px·저장 버튼51.75px를 확인했습니다. 비우기 뒤 입력 값·비교·보고서가 해제됐습니다. 이는 알려진 합성 파일의 새 보고서 기능 검증이며 실제 서버 파일의 진위나 패킷 캡처 시험이 아닙니다. URL/DOM 생성 실패의 유한 안내와 정리는 합성 handler 검사로 확인했습니다. 기존 파일 입력의 완료 검사나 PR271의 결과를 이번 다운로드 검증으로 바꾸지 않습니다.

정확 source 독립 검토·같은 main의 CI·Pages·공개 실제 다운로드는 대기 중입니다. 완료한 범위만 후속 기록합니다.

Pages 토큰 교체·별도 환경 K3s/Jenkins 기동 복원·예산 정책·PR #102와 운영 image/source pin은 유지합니다.
