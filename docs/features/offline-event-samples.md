# 파일이 없을 때 예제로 비교하기

[저장한 이벤트 JSON 비교](https://devdooly.github.io/devdooly-platform-lab/runs/offline/)의 **파일이 없다면 예제로 시작**에서 작은 합성 파일 두 개를 받습니다. 별도 API 조회나 실행 생성 없이 기존 파일 선택·비교·보고서 저장을 체험하는 자료입니다. 실제 운영 데이터·worker 실행·장애 복구·성능 측정 기록이 아닙니다.

1. **A 예제 JSON 받기 (v1)**와 **B 예제 JSON 받기 (v2)**를 각각 눌러 저장합니다.
2. 아래 A·B 파일 선택에서 저장한 두 파일을 고르고 **선택한 파일 비교**를 누릅니다. 다운로드만으로 파일을 읽거나 비교를 자동 실행하지 않습니다.
3. 다섯 비교 분류를 살펴보고 검색·분류를 바꾼 뒤 **비교 보고서 JSON 저장**으로 현재 조건의 결과를 남깁니다.

정적 페이지·예제 파일을 처음 내려받는 연결은 필요합니다. 별도 오프라인 설치나 PWA를 추가하지 않습니다. 다운로드 요청과 실제 파일 저장 여부는 브라우저에서 확인합니다.

## 예제 파일과 기대 결과

| 파일 | 형식·저장 행 | 파일에 적힌 조건·건수 |
| --- | --- | --- |
| [A 예제](../../apps/lab-web/public/examples/offline-events-a-v1.json) | schemaVersion1·6행 | ALL·빈 query·reason null, 센서 필드 없음. reported/available/matched=6/6/6 |
| [B 예제](../../apps/lab-web/public/examples/offline-events-b-v2.json) | schemaVersion2·4행 | 같은 조건에 sensorId=`sample-sensor` 정확 조건. reported/available/matched=6/4/4 |

두 파일의 source.mode는 `fixture`, observedAt·capturedAt은 모두 `null`입니다. eventTime의 `2000-01-01T00:00:00Z`는 예제 입력에 넣은 합성 시각이며 실제 관측 시각이 아닙니다. 모든 행은 `sample-sensor`를 사용합니다. JSON에는 기존 reader가 받지 않는 설명 필드를 덧붙이지 않았습니다.

| sequence | 기대 분류 | 나란히 확인할 것 |
| --- | --- | --- |
| 1 | 비교 필드 같음 | 양쪽 입력 값25·SUCCESS/ACCEPTED |
| 2 | 판정 필드 다름 | 같은 입력 값30, A SUCCESS/ACCEPTED · B FAILED/SYNTHETIC_REVIEW |
| 3 | 보고된 입력 필드 다름 | 값120→40과 판정 차이. 입력 차이 분류를 우선 |
| 4 | 한쪽 미관측 | A에만 저장된 행. 처리 누락의 증거가 아님 |
| 5 | 대응 모호 | A후보2행·B후보1행을 임의로 한 쌍으로 만들지 않음 |

전체는 **5그룹·다섯 분류 각각1개**입니다. A의6행과 B의4행을 원본 이벤트10개나 동일한 전체 입력으로 해석하지 않습니다. 예제 판정은 설명용 합성 기록이며 당시 Java 규칙·실행 코드·회귀·수정 효과를 증명하지 않습니다. [파일 비교의 해석 범위](offline-event-comparison.md)와 [별도 보고서 형식](offline-comparison-report.md)을 따릅니다.

## 검증 상태

구현 후 공개 검증 전입니다. 실제 정적 파일의 기존 v1/v2 reader 수용·수기 기대 분류·모든 후보와 report 호환 검사는 최초3개를 통과했고, 웹 전체508개·Astro86파일 진단0·5페이지 빌드를 확인했습니다. 독립 검토에서도 정적 자산·빌드 경로·계약·UI에 소스 결함을 찾지 못했습니다.

로컬의 두 정적 URL에서 표시되는 JSON이 소스와 같고, 그 소스 파일을 기존 입력기로 직접 선택해 5분류각1·모든 후보를 확인했습니다. 실제 저장된 비교 보고서5,051bytes의 출처·조건·건수·모든 원문 행도 일치했습니다. 375px에서 가로 넘침 없이 17px본문·51.75px다운로드 링크와 Enter로 여는 기대 결과를 확인했습니다.

단, 로컬 브라우저의 A 정적 링크 다운로드는 이벤트 대기10초와 downloadMedia30초가 모두 시간 초과했습니다. 예상 경로에 파일이 없었으며 B는 시도하지 않았습니다. 같은 화면의 보고서 다운로드는 성공했지만 정적 파일 다운로드 성공으로 대체하지 않습니다. 원인은 미확정이고 소스 결함이나 브라우저 도구 문제로 단정하지 않습니다. 정확 source·같은 main CI/Pages·공개 실제 다운로드는 후속 확인 대상입니다. 기존 파일 비교·보고서 전체 검증을 이번 예제 기능의 검증으로 대체하지 않습니다.

기존 reader·비교/보고서·API·공유/내보내기 형식과 운영 pin을 보존합니다. Pages 토큰 교체·별도 환경 K3s/Jenkins 기동 복원·예산 정책·PR #102는 계속 보류합니다.
