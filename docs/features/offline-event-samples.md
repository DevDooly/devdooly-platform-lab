# 파일이 없을 때 예제로 비교하기

[저장한 이벤트 JSON 비교](https://devdooly.github.io/devdooly-platform-lab/runs/offline/)의 **파일이 없다면 예제로 시작**에서 작은 합성 파일 두 개를 받습니다. 별도 API 조회나 실행 생성 없이 기존 파일 선택·비교·보고서 저장을 체험하는 자료입니다. 실제 운영 데이터·worker 실행·장애 복구·성능 측정 기록이 아닙니다.

1. **A 예제 JSON 받기 (v1)**와 **B 예제 JSON 받기 (v2)**를 각각 눌러 저장합니다.
2. 아래 A·B 파일 선택에서 저장한 두 파일을 고르고 **선택한 파일 비교**를 누릅니다. 다운로드만으로 파일을 읽거나 비교를 자동 실행하지 않습니다.
3. 다섯 비교 분류를 살펴보고 검색·분류를 바꾼 뒤 **비교 보고서 JSON 저장**으로 현재 조건의 결과를 남깁니다.

정적 페이지·예제 파일을 처음 내려받는 연결은 필요합니다. 별도 오프라인 설치나 PWA를 추가하지 않습니다. 다운로드 요청과 실제 파일 저장 여부는 브라우저에서 확인합니다.

## 예제 파일과 기대 결과

| 파일 | 형식·저장 행 | 파일에 적힌 조건·건수 |
| --- | --- | --- |
| [A 예제](../../apps/lab-web/public/examples/offline-events-a-v1.json) | schemaVersion1·6행 | ALL·빈 query·reason null, 센서 필드 없음. reported/available/matched=6/6/6 |
| [B 예제](../../apps/lab-web/public/examples/offline-events-b-v2.json) | schemaVersion2·4행 | 같은 조건에 sensorId=`sample-sensor` 정확 조건. reported/available/matched=6/4/4 |

두 파일의 source.mode는 `fixture`, observedAt·capturedAt은 모두 `null`입니다. eventTime의 `2000-01-01T00:00:00Z`는 예제 입력에 넣은 합성 시각이며 실제 관측 시각이 아닙니다. 모든 행은 `sample-sensor`를 사용합니다. JSON에는 기존 reader가 받지 않는 설명 필드를 덧붙이지 않았습니다.

| sequence | 기대 분류 | 나란히 확인할 것 |
| --- | --- | --- |
| 1 | 비교 필드 같음 | 양쪽 입력 값25·SUCCESS/ACCEPTED |
| 2 | 판정 필드 다름 | 같은 입력 값30, A SUCCESS/ACCEPTED · B FAILED/SYNTHETIC_REVIEW |
| 3 | 보고된 입력 필드 다름 | 값120→40과 판정 차이. 입력 차이 분류를 우선 |
| 4 | 한쪽 미관측 | A에만 저장된 행. 처리 누락의 증거가 아님 |
| 5 | 대응 모호 | A후보2행·B후보1행을 임의로 한 쌍으로 만들지 않음 |

전체는 **5그룹·다섯 분류 각각1개**입니다. A의6행과 B의4행을 원본 이벤트10개나 동일한 전체 입력으로 해석하지 않습니다. 예제 판정은 설명용 합성 기록이며 당시 Java 규칙·실행 코드·회귀·수정 효과를 증명하지 않습니다. [파일 비교의 해석 범위](offline-event-comparison.md)와 [별도 보고서 형식](offline-comparison-report.md)을 따릅니다.

## 검증 상태

[PR277](https://github.com/DevDooly/devdooly-platform-lab/pull/277)의 예제·안내를 공개했습니다. 실제 정적 파일의 기존 v1/v2 reader 수용·수기 기대 분류·모든 후보와 report 호환 검사는 최초3개를 통과했고, 웹 전체508개·Astro86파일 진단0·5페이지 빌드와 같은 main의 CI·Pages를 확인했습니다. 독립 검토에서도 정적 자산·빌드 경로·계약·UI에 소스 결함을 찾지 못했습니다.

로컬의 두 정적 URL에서 표시되는 JSON이 소스와 같고, 그 소스 파일을 기존 입력기로 직접 선택해 5분류각1·모든 후보를 확인했습니다. 실제 저장된 비교 보고서5,051bytes의 출처·조건·건수·모든 원문 행도 일치했습니다. 375px에서 가로 넘침 없이 17px본문·51.75px다운로드 링크와 Enter로 여는 기대 결과를 확인했습니다.

단, 로컬 브라우저의 A 정적 링크 다운로드는 이벤트 대기10초와 downloadMedia30초, 공개본의 A Enter 동작은15초 대기에서 시간 초과했습니다. 예상 경로에 파일이 없었으며 B는 시도하지 않았습니다. 같은 화면의 보고서 다운로드는 성공했지만 정적 파일 다운로드 성공으로 대체하지 않습니다. 원인은 미확정이고 소스 결함이나 브라우저 도구 문제로 단정하지 않습니다.

이 사용 경로를 보완하기 위해 원래 두 정적 JSON을 유일한 자료로 유지하며 빌드 시 그 UTF-8 원문을 페이지에 포함하고, 명시 클릭·Enter에서만 브라우저 Blob으로 저장을 요청하도록 했습니다. JSON을 다시 직렬화하지 않고 원문을 사용하며 JS 미준비·수정키 동작의 원래 링크는 유지합니다. 다운로드 요청은 파일 저장 성공 표시와 다릅니다.

후속 UI의 첫 웹508개·Astro86파일 진단0·5페이지 빌드도 통과했습니다. 빌드 미리보기에서 A·B를 Enter로 각각 한 번 실제 저장하고, 1,649/1,251bytes가 원 정적 파일과 정확히 일치함을 확인했습니다. 그 두 다운로드 파일을 기존 입력기로 비교해 다섯 분류각1·모든 후보와 실제 보고서5,051bytes를 확인했습니다. 다운로드만으로 자동 선택·비교가 생기지 않았고, 기존 비우기를 Enter로 실행해 선택과 표시가 해제되는 것도 확인했습니다. 이 성공은 앞선 클릭 후 잔류 관측이나 정적 링크 시간 초과의 원인을 설명하지 않습니다. 375px 가로 넘침 없음·17px본문·51.75px링크·기대 결과 Enter 펼침도 확인했습니다.

[PR279](https://github.com/DevDooly/devdooly-platform-lab/pull/279)의 후속 경로도 공개 검증을 마쳤습니다. 검토 source `3675f72e0b65b59f1cacf1cb51c4a6da0d67d76f`와 main `e1c5c2e4acdd018cb276e0a541ef8c03bded45a8`의 전체 tree가 일치하며, 같은 main의 [CI](https://github.com/DevDooly/devdooly-platform-lab/actions/runs/40194799005)·[Pages](https://github.com/DevDooly/devdooly-platform-lab/actions/runs/40194799081)가 성공했습니다. 공개 A 클릭·B Enter 각각 한 번의 실제 다운로드 파일1,649/1,251bytes가 원문과 정확히 일치했고, 그 두 파일을 다시 선택해 다섯 분류각1·모든 후보·실제 비교 보고서5,059bytes를 확인했습니다. 보고서는 브라우저가 중복 저장 파일명에 붙인 `(1)`까지 보존해 로컬 보고서와8bytes 차이가 나며, 양쪽 출처·조건·건수·전체 행은 같습니다.

공개 다운로드만으로 자동 선택·비교가 없고, Enter 비우기의 선택·표시 해제와375px·17px·51.75px·기대 결과 펼침도 확인했습니다. 독립 검토는 실제 저장 파일과 보고서·메타데이터를 대조했으며, UI·Git·전체검사·브라우저를 서로 중복 실행하지 않았습니다. JS를 끈 원래 링크 저장·수정키 동작·브라우저 강제 실패는 실제 브라우저 검증 범위가 아닙니다. 기존 파일 비교·보고서 전체 검증을 이번 예제 기능의 검증으로 대체하지 않습니다.

기존 reader·비교/보고서·API·공유/내보내기 형식과 운영 pin을 보존합니다. Pages 토큰 교체·별도 환경 K3s/Jenkins 기동 복원·예산 정책·PR #102는 계속 보류합니다.
