# 이벤트 JSON 한 개 다시 보기

[파일 탐색 화면](https://devdooly.github.io/devdooly-platform-lab/runs/view/)에서 ‘이벤트 상세 → 검색 결과 저장’으로 받은 JSON 하나를 다시 읽습니다. 서비스 목차와 기존 두 파일 비교 화면에서 들어갈 수 있습니다.

## 이용 순서

1. JSON 한 개를 선택하고 **선택한 파일 열기**를 누릅니다. 선택만 바꾸면 이전에 연 결과는 그대로입니다.
2. 파일 이름·형식·저장 행 수와 파일에 기록된 출처·시각·세 건수·원래 검색 조건을 확인합니다.
3. 이 화면의 eventId·sensorId 부분 검색, 상태·원문 사유·정확한 센서 조건으로 저장된 행을 좁힙니다. 조건 초기화는 파일에 포함된 모든 행을 보여주며, 원래 내보내기 때 제외된 행을 복구하지 않습니다.
4. 페이지별로 행을 보고 원하는 행의 원문 필드를 확인합니다. 같은 sequence·eventId가 반복되어도 파일 안의 행 위치로 구분합니다.
5. 다른 파일을 성공적으로 열면 새 파일과 초기 조건으로 전환합니다. 읽기·검증 실패 시 이전 성공 결과는 보존합니다. 비우기는 선택한 파일·열린 결과·검색·행 선택을 함께 지웁니다.

파일이 없다면 [합성 예제](offline-event-samples.md)의 A(v1) 또는 B(v2)를 사용할 수 있습니다. 예제는 실제 운영 자료가 아닙니다. 두 파일을 비교하려면 [별도 비교 화면](offline-event-comparison.md)을 사용합니다.

## 파일과 출처

기존 `readOfflineEventFile`을 그대로 사용합니다. UTF-8 이벤트 내보내기 schemaVersion 1·2, 파일당 1 MiB·1,000행까지이며 중복 object key·필드·건수·기록 필터와 저장 행의 일치를 검사합니다. [기존 검증 범위](offline-event-comparison.md)를 따르며 비교 보고서 JSON이나 임의 API 응답을 이벤트 파일로 받아들이지 않습니다.

원파일의 `mode`·runId·observedAt·capturedAt은 **파일에 기록된 값**입니다. 파일의 진위·현재 API 상태를 인증하지 않습니다. `null` 시각은 그대로 표시하며 지금 파일을 연 시각으로 대체하지 않습니다. 보고된 입력 수, 당시 조회된 행 수, 당시 조건에 맞아 저장된 행 수와 **이 화면의 조건 일치 수**를 구분합니다. 저장 행 수가 다른 건수와 같아도 원본 전체의 완전성을 증명하지 않습니다.

원문 문자열·숫자·null과 행 순서를 유지합니다. 중복 sequence를 합치거나 원문 eventTime을 다른 시각으로 변환하지 않습니다. value가 null이면 원래 null인지 JSON 직렬화된 비유한 값인지 복원하지 않습니다. 원래 파일의 검색 조건과 새 화면의 검색 조건은 별개입니다.

## 처리 범위

파일은 사용자의 명시적 열기 동작으로 브라우저 메모리에 읽습니다. 파일 내용을 서버로 전송하거나 브라우저 저장소에 보관하지 않습니다. 새 GET·작업 실행·재판정·공유 링크·재내보내기·비교 보고서 복원은 포함하지 않습니다. 읽기 중에는 파일·검색·비우기 조작을 잠그며, 화면을 벗어난 뒤 완료된 읽기를 적용하지 않습니다.

## 검증 상태

이번 변경의 실제 검사·로컬 화면·병합된 main의 CI/Pages·공개 결과를 PR 완료 기록에 구분합니다. 코드 작성만으로 공개 반영이나 실제 파일 선택 성공을 표시하지 않습니다. 기존 운영 pin·네 보류와 이전 HTTP429 등 실패 기록은 유지합니다.
