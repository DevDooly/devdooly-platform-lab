# API 상세 응답 요약

[API 안내](https://devdooly.github.io/devdooly-platform-lab/api-guide/#api-detail)에서 실행을 선택하거나 ID를 입력한 뒤 **GET으로 직접 조회**를 누릅니다. 성공한 상세 응답의 형식과 요청 ID 일치를 확인하면 다음 내용을 JSON 위에 표시합니다.

- 실제 응답의 실행 ID·이름·시나리오·상태
- 응답이 보고한 입력·성공·실패·중복·대기 건수
- 응답에 포함된 이벤트 행 수
- 같은 실행의 전체·실패 이벤트로 이어지는 링크

처리 건수와 포함 행 수는 별개입니다. 이 화면은 행 수로 처리 건수를 다시 계산하거나 보고된 수치를 실제 재실행의 결과로 인증하지 않습니다. 기존 API 관측 시각·브라우저 수신 시각과 원 JSON 확인·복사를 유지합니다.

## 선택과 응답의 구분

A를 조회한 뒤 입력칸에서 B를 선택하기만 하면 A의 요약과 링크가 남고 기존 선택 변경 안내가 표시됩니다. B를 실제로 요청하면 기존 콘솔의 loading/error/success 상태에 따라 표시합니다. 실패한 새 요청에 A의 요약을 성공 결과처럼 남기지 않습니다.

HTTP·JSON 수신 성공과 상세 요약 가능 여부를 구분합니다. 상세 형식이나 요청/응답 ID 일치를 확인하지 못하면 요약·이벤트 링크를 숨기고 고정 안내를 표시합니다. 수신한 JSON은 기존 방식으로 펼쳐 볼 수 있습니다. 다른 다섯 API의 응답 표시 방식은 유지합니다.

## 이벤트 화면으로 이동

링크는 표시 중인 응답의 실행 ID와 ALL 또는 FAILED 조건으로 만듭니다. 수신한 응답을 다른 화면에 전달하거나 영구 저장하지 않습니다. 도착한 화면에서 **공유한 실행·조건 조회**를 누르면 같은 ID를 새로 읽으므로 응답과 시각이 달라질 수 있습니다. 실패 0건인 실행도 실패 조건을 열 수 있으며 결과가 없을 수 있습니다.

요약을 그리거나 입력칸만 바꿀 때 추가 GET은 없습니다. 기존 명시 GET·8초 제한·본문 크기 제한·인증정보 미전송 정책과 운영 API·이미지·데이터는 그대로입니다.

## 검증 상태

로컬 웹 검사 536개(실패·생략 0), Astro 88파일 진단 0, 5페이지 빌드를 통과했습니다. 합성 HTTP 서버와 실제 브라우저에서 정상 12/7/3/2/0 요약, 입력 ID만 변경한 뒤 이전 응답 구분, 요청/응답 ID 불일치·불완전 DTO의 요약 억제와 JSON 유지, 후속 HTTP429의 이전 요약 제거를 확인했습니다. 375px 화면에서 가로 넘침이 없고 이벤트 링크 높이는 50px였습니다. 합성 오류 입력은 운영 장애 재현과 구분합니다.

같은 main의 CI/Pages·공개 화면은 PR 완료 기록에 별도로 남깁니다. 위 로컬 검증만으로 공개 배포나 운영 가용성 확인을 완료했다고 표시하지 않습니다. PR267·281의 기존 운영429 기록은 보존합니다.
