# 작업 관측에서 이벤트 결과로 이동

작업 카드에서 실패 건수를 확인한 뒤 긴 실행 ID를 다시 찾던 흐름을 연결합니다. [작업·export 관측](https://devdooly.github.io/devdooly-platform-lab/#job-observation)의 완료 작업에서 **전체 이벤트 보기** 또는 **실패 이벤트 보기**를 누르세요. 이동한 실행 결과 화면에서 **공유한 실행·조건 조회**를 누르면 해당 ID를 새로 조회합니다.

## 연결 조건과 의미

- `MINI_PC` / `DEPLOYED_RUNTIME` 관측의 `COMPLETED` 작업에만 연결합니다. DB 처리 완료는 같은 `runId`의 `demo_run` 저장과 한 트랜잭션으로 기록됩니다.
- 실패 이벤트 링크는 관측의 실패 건수가 1개 이상일 때 표시합니다. 조건은 `FAILED`이며 검색어·사유·센서·선택 이벤트는 지정하지 않습니다.
- export `PENDING`·`EXPORTED`·`CANCELLED`는 이미 DB에 처리 결과가 있는 상태이므로 연결할 수 있습니다. export 완료나 파일 가용성을 추가로 주장하지 않습니다.
- 처리 전 `STAGING`·`QUEUED`·`TERMINATED`에는 링크를 표시하지 않습니다. 로컬·격리 시험 관측도 운영 API 결과에 연결하지 않습니다.
- 기존 [실행·검색 공유 형식](event-share.md)을 사용합니다. URL에는 실행 ID와 필터만 들어가며 시각·응답·자격증명은 포함하지 않습니다. GitHub Pages 경로와 로컬 루트 경로를 모두 지원합니다.

링크의 실행·조건은 버튼을 눌러야 적용합니다. 대상 화면의 기존 초기 목록·기본 상세 조회와 관측 주기는 유지되며, 버튼을 누른 뒤 요청한 작업의 상세 조회는 **새 관측**입니다. 원 작업 관측 시각의 고정 응답이나 S3 결과 파일을 내려받는 기능이 아닙니다. API 조회가 실패하거나 실행이 없으면 기존 상세 화면을 보존하는 동작을 그대로 따릅니다.

## 검증 상태

- 로컬 웹 검사 517개 통과·생략 0, Astro 87파일 진단 0, Pages 경로로 5페이지 빌드를 확인했습니다.
- 신규 계약 7개와 UI 통합 2개는 완료/미완료·export 상태·출처 범위·실패 0·원 ID/필터 연결·입력 보존을 검증합니다. 나머지 기존 검사를 유지합니다.
- 로컬 브라우저에서 실제 완료 작업의 링크를 키보드로 열고 명시적 조회 뒤 실패 3건을 확인했습니다. 375px 화면의 링크 높이는 약 52.6px이며 가로 넘침이 없었습니다. 전체 이벤트 링크의 ALL 조건 전달까지 확인했으나 해당 로컬 재조회는 기존 공개 API의 HTTP 429로 중단했습니다. 이전 결과와 조회 불가 안내를 보존한 상태이며 전체 재조회 성공으로 표시하지 않습니다.
- 로컬 최초 proxy는 실행 환경의 네트워크 제한 `EACCES`로 조회하지 못했습니다. 승인된 공개 GET 연결로 실패 이벤트 흐름을 확인했으며 이 제한을 제품 오류나 운영 장애로 표시하지 않습니다.
- 공개 브라우저의 결과와 동일 main CI·Pages 실행은 이 기능의 PR 완료 기록에서 별도로 확인합니다. 소스·로컬 검사만으로 공개 반영을 완료로 간주하지 않습니다.

새 API·작업·데이터 수정 없이 웹 조회 동선만 변경합니다. Pages 토큰 교체, 별도 환경 기동 복원, 자원 예산 정책, PR #102 및 운영 image/source pin은 유지합니다.
