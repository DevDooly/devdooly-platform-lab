# 이벤트 검색과 사유 필터

기준: 2026-10-24 KST. [Java 처리 결과](https://devdooly.github.io/devdooly-platform-lab/#lab)의 이벤트 상세에서 이미 읽은 최대 1,000건을 찾는 기능입니다. [이벤트 판정 흐름](event-flow.md)의 원문·출처·시각과 해석 범위를 유지합니다.

## 검색 조건

검색어의 양끝 공백을 제거한 뒤 eventId 또는 sensorId에 포함되는지 대소문자를 구분하지 않고 비교합니다. 정규식이나 와일드카드가 아닌 문자 그대로의 부분 검색이며, 공백뿐인 검색어는 검색 조건을 제한하지 않습니다. 표시하는 ID 원문은 바꾸지 않습니다.

사유는 응답의 원시 reason 문자열과 정확히 일치하는 값을 선택합니다. 사유의 대소문자·공백을 정규화하거나 알려진 코드로 치환하지 않습니다. 미지의 사유도 원문으로 다루고 빈 문자열은 전체 사유 선택과 구분합니다. 검색어·사유·기존 status 조건은 AND로 적용하며, ID 검색 안에서만 eventId 또는 sensorId 중 하나가 일치하면 됩니다.

## 표와 흐름 선택

이벤트 표와 **흐름을 볼 이벤트** 목록은 같은 조건의 결과를 사용합니다. 응답의 입력 순서를 유지하고 eventId가 반복되어도 행을 합치지 않습니다. 기존 실행 ID·출처·sequence의 선택 구분과 응답 필드 원문도 유지합니다. 검색 결과 수는 현재 응답에서 조건에 맞는 행 수이며 서버가 보고한 실행 전체 건수나 판정을 다시 계산한 값이 아닙니다.

어느 조건이든 바꾸면 현재 흐름 선택을 비우고 사용자가 다시 선택하도록 합니다. 다른 검색 조건은 임의로 초기화하지 않으며 표·흐름 사이를 이동해도 조건을 유지합니다. **전체 초기화**는 검색어·사유·status 조건과 흐름 선택을 함께 비웁니다. 결과가 없으면 빈 결과와0건을 표시하며 숨겨진 행이나 첫 이벤트를 자동 선택하지 않습니다.

검색 입력·선택·초기화는 화면의 이벤트 연결 준비 전과 조회 중에 잠급니다. 검색은 현재 읽어 둔 이벤트에만 적용하며 조건 변경으로 추가 GET·서버 재판정·새 실행을 요청하지 않습니다. 기존 실행 선택·명시적인 재조회 기능의 요청과 구분합니다.

## 검증

순수 검색7개와 컨트롤 SSR3개를 추가해 전체 웹310개·생략0, Astro65파일 진단0·4페이지 빌드를 통과했습니다. V1의 독립 기대 sequence, literal 특수문자·trim·대소문자, 복합 조건, 원문·중복 행·입력 객체 보존과 합성1,000행의 마지막 검색을 확인했습니다. SSR에서는 준비 전 잠금과 빈 사유·전체·sentinel과 같은 사유의 구분, 새 실행에 없는 사유와 조건 표시를 확인합니다.

별도 로컬 브라우저는 기존 공개 API의 저장된 실행을 읽었습니다. 12건의 `EVT-003` 검색은 sequence3·4를 유지하고 사유 선택은4만 남겼습니다. 실제1,000건에서는 `MAX-SENSOR-099` 검색으로991~1,000의10행을 찾고 FAILED·OUT_OF_RANGE를 함께 골라996행의 원래 값120을 확인했습니다. 표와 흐름 목록 일치, 키보드 Enter 선택·상세 초점, 조건 변경 시 선택 해제·0건·초기화, 다른 실행에서 검색 조건 유지와 조회 중 입력 잠금을 확인했습니다. 모바일375px에서 가로 넘침0,17px 글자와49px 이상 입력·버튼을 확인했습니다.

검색은 이미 읽은 배열에만 적용하며 추가 요청 호출은 없습니다. 이번 로컬 확인은 새 Java 실행·운영 장애 주입·가용성 검증이 아닙니다. 병합 main의 CI·Pages와 실제 공개 이용 흐름은 PR 검증 기록에 별도로 남깁니다.

Pages 토큰 교체·별도 환경의 K3s/Jenkins 기동 복원·자원 예산 정책·PR #102는 계속 보류합니다. 운영 image/source pin·기존 서비스·데이터는 변경하지 않으며 브라우저 검색으로 운영 상태나 가용성을 새로 검증하지 않습니다.
