# 이벤트 판정 흐름 탐색

기준: 2026-10-24 KST. [Java 처리 결과](https://devdooly.github.io/devdooly-platform-lab/#lab)의 기존 이벤트 표에서 한 이벤트의 응답 필드·사유 코드·결과 분류를 함께 살펴보는 기능입니다.

## 사용 방법

1. Java 처리 결과에서 실행을 고르고 **이벤트 상세** 탭을 엽니다.
2. 상태 필터를 고른 뒤 행의 **흐름 보기**를 누릅니다. 위의 **흐름을 볼 이벤트** 목록에서도 선택할 수 있습니다.
3. **응답에 남은 이벤트 필드 → 보고된 판정 사유 → 보고된 결과 분류** 세 카드를 읽습니다. eventTime·value·reason·status는 응답 원문을 유지합니다.

같은 eventId가 반복되어도 실행 ID·표시 출처·sequence로 선택을 구분합니다. 필터를 바꾸면 선택을 비우고, 다른 실행이나 출처의 같은 sequence를 이전 선택으로 표시하지 않습니다. 선택한 제목으로 초점을 옮겨 키보드로도 상세를 따라갈 수 있습니다. 이벤트 선택은 이미 읽은 결과를 사용하며 추가 API 요청이나 작업 실행을 하지 않습니다.

## 근거와 해석 범위

표시 출처는 `live · API 조회`, `recorded · 게시 관측`, `fixture · 고정 샘플 기대값`으로 구분합니다. runId·observedAt 원문을 표시하고 게시본·fixture의 capturedAt도 따로 표시합니다. fixture는 DB에 저장된 실행의 관측으로 해석하지 않습니다.

사유 설명은 [고정 Java SensorProcessor · fda29d1](https://github.com/DevDooly/devdooly-platform-lab/blob/fda29d1647fb40b9312bbcd50b77eeefcab926e3/apps/api/src/main/java/io/github/devdooly/platformlab/demo/SensorProcessor.java)의 규칙을 참고합니다. 기본 입력 → 실행 내 eventId 중복 → Java 시각 해석 → 값 범위 0~100 → 센서별 최신 성공 시각 → 수용 순서입니다. 시각·범위·순서 조건에서 실패한 ID도 중복 판단에 기억하지만 기본 입력이 유효하지 않으면 등록하지 않습니다. 같은 시각과 경계값 0·100은 허용하며 성공만 최신 센서 시각을 갱신합니다.

현재 참고 구현은 성공·실패·중복 결과를 모두 저장합니다. SUCCESS만 시계열에 포함되고 FAILED만 실패 사유 집계에 포함됩니다. 알려진 status·reason 쌍만 해당 해설에 연결하며 PENDING·미지의 사유·서로 맞지 않는 조합은 원래 보고값과 미확인 안내를 유지합니다.

DTO는 단계별 trace·단계별 소요 시간·실행 당시 코드 버전을 제공하지 않습니다. 브라우저에서 값을 재판정하거나 보이지 않는 단계를 PASS로 만들지 않습니다. 응답의 value=null만으로 원본 null·NaN·무한대를 구분할 수 없습니다. Kafka 발행·DB 저장·S3 export의 개별 실행 이력을 추가한 기능도 아닙니다.

## 검증

알려진 판정 쌍·미지 조합·원문 보존·sequence 선택·필터와 출처를 검증하는 helper4개·SSR3개를 추가했습니다. 로컬 전체 웹300개·생략0, Astro64파일 진단0·4페이지 빌드를 통과했습니다. 실제 로컬 화면에서는 시각 형식·역순·범위 실패, 같은 ID의 성공/중복 구분, 필터·빈 결과·실행 전환·행 재선택 초점과 데스크톱/모바일을 확인했습니다. 모바일 본문375px에서 가로 넘침 없이17px 글자·49px 선택 상자와 한 열 카드를 확인했습니다.

첫 화면 확인에서 새 선택의 제목만 화면 하단에 걸려 카드를 바로 보기 어려워, 제목을 화면 위쪽으로 이동하도록 보완했습니다. 병합 main의 CI·Pages·공개 데스크톱/모바일 결과는 PR의 검증 기록에 별도로 남깁니다. 로컬 검증만으로 공개 반영이나 운영 가용성을 완료로 표시하지 않습니다.

Pages 토큰 교체·별도 환경 기동 복원·자원 예산 정책·PR #102는 계속 보류합니다. 기존 운영 image/source pin·서비스·데이터를 변경하지 않습니다.
