# 공개 GET 요청 명령 복사

[API 안내](https://devdooly.github.io/devdooly-platform-lab/api-guide/)의 여섯 API에서 **터미널용 GET 명령 보기·복사**를 펼칩니다. macOS·Linux·Git Bash는 `curl`, Windows PowerShell은 `curl.exe`를 선택하고 **GET 명령 복사**를 누릅니다. curl이 설치된 터미널에 붙여넣어 사용자가 직접 실행합니다.

## 현재 요청과 이전 응답

명령은 현재 API 주소·선택한 실행 ID를 사용합니다. A를 조회한 후 입력칸을 B로 바꾸면 명령은 B를 가리키고, 기존 응답·요약은 A로 남습니다. 기존 선택 변경 안내를 유지합니다. ID를 바꾸어도 펼친 명령과 터미널 선택은 유지하고 이전 복사 알림은 지웁니다. 새 명령을 실행하면 시각과 결과가 달라질 수 있습니다.

펼치기·터미널 선택·복사는 API를 호출하지 않습니다. 생성한 명령을 브라우저에서 실행하거나 조회 버튼과 함께 실행하지 않습니다. 준비 전 복사·선택은 잠기며 클립보드 복사에 실패하면 표시된 명령을 직접 선택해 복사할 수 있습니다.

## 대상과 명령의 범위

- 기존 여섯 공개 GET 경로만 사용합니다. 상세 ID는 기존 최대 80자 규칙을 따르며 개행·따옴표·셸 특수 문자는 명령에 넣지 않습니다.
- 검증한 절대 HTTPS API 주소를 사용합니다. `/api` 설정은 현재 HTTPS 사이트의 origin으로 주소를 만들고 같은 주소 규칙으로 재검증합니다. HTTP 로컬 개발에서는 명령을 만들지 않으며 기존 브라우저 GET 기능은 유지합니다.
- 첫 옵션 `-q`로 기본 curl 설정 파일을 읽지 않습니다. GET·JSON Accept 헤더·연결 5초·전체 8초 제한과 `--silent --show-error --fail`을 사용합니다. 명령에 로그인·토큰·쿠키·인증서 검증 해제·자동 재시도·리디렉션 따라가기 옵션을 추가하지 않습니다.
- HTTP 오류는 curl 실패로 반환하지만 이 명령은 브라우저의 256 KiB 제한, JSON 파싱, 상세 DTO 검증을 수행하지 않습니다. CORS와 사용자 터미널의 네트워크 환경도 브라우저와 다릅니다. 명령 생성·복사는 API 가용성이나 처리 성공의 증명이 아닙니다.

## 검증 상태

명령 생성 검사는 여섯 경로·두 터미널·현재 ID·상대 API origin·길이·개행·셸 문자 거부를 다룹니다. SSR 검사는 준비 전 입력 잠금·접힘·안내와 잘못된 대상의 명령/복사 억제를 확인합니다. 실제 실행 결과와 로컬/공개 브라우저 확인 범위는 PR 완료 기록에 구분해 남깁니다. 생성한 명령의 실제 터미널 실행과 클립보드 권한 거부는 이번 자동 검증 범위에 포함하지 않습니다.

운영 API·이미지·데이터·기존 실패 기록을 변경하지 않습니다. Pages 토큰 교체, 격리 기동 복원, 예산 정책, PR102 보류를 유지합니다.
