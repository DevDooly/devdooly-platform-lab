# 0001 개인 플랫폼의 범위와 구성

- 상태: 설계 채택, API·화면 MVP 구현. 미니 PC 플랫폼 적용 전
- 결정일: 2026-10-11

## 배경

Java·데이터 처리·배포·운영 경험을 소스와 화면으로 확인할 수 있는 포트폴리오가 필요합니다. Ubuntu 미니 PC는 Ryzen 7 5700, 32GiB RAM이며 약 200GB의 여유 공간이 있습니다. 기존 서비스가 있으므로 실제 사용량을 확인하고 단계적으로 구성합니다.

## 결정

1. 공개 소개는 GitHub Pages의 Astro·React 정적 사이트로 구성합니다. 기존 MkDocs TIL은 유지합니다.
2. 실행형 Lab은 K3s 단일 노드의 Spring Boot API, MariaDB와 Astro·React UI로 시작합니다.
3. Jenkins는 테스트·이미지 게시·GitOps 변경 PR을, Argo CD는 Helm 선언의 동기화를 맡습니다. 배포 상태의 기준은 GitOps commit과 실제 서비스 버전입니다.
4. Kafka·S3는 기본 동작과 배포를 검증한 후 추가합니다. Iceberg·Spark·Trino는 필요할 때 실행하는 확장으로 둡니다.
5. 공개 화면에는 합성 데이터와 허용한 운영 요약만 제공합니다. 관리 도구는 사설 접속 또는 별도 인증 뒤에서 사용합니다.
6. 검토한 실행 기록을 정적 홈에도 게시해 Lab 연결 실패 때 이전 결과와 관측 시각을 표시합니다.

## 결과와 한계

작은 기능부터 전체 배포 흐름을 검증할 수 있습니다. 단일 물리 서버는 장애에 견디는 HA가 아니며 local-path PV의 데이터와 자격증명은 별도 백업이 필요합니다. 정적 홈과 Lab을 함께 관리하고 공개용 snapshot을 갱신하는 작업도 필요합니다.

## 아직 정하지 않은 것

- 언어·프레임워크·빌드 도구·chart의 실제 버전
- SSH 접속 설정, 설치 경로, 기존 서비스와 공존할 자원 배정
- Pages 저장소·주소, 외부 HTTPS 방식, 별도 백업 위치
- S3 제품과 Iceberg catalog

위 항목은 해당 단계의 검증 결과로 결정합니다. 이 결정만으로 애플리케이션이나 서버의 구축 완료를 의미하지 않습니다.

## 다시 검토할 조건

실제 가용 자원이 예산보다 작거나, 공개 기능이 사용자별 로그인·서버 렌더링을 요구하거나, 단일 서버로 유지할 수 없는 데이터량이 확인되면 범위를 조정하고 새 ADR을 작성합니다.
