# 단계별 작업과 완료 조건

체크된 항목은 확인된 결과가 있는 작업입니다. 계획 단계의 기능에는 체크하지 않습니다. 서버 구현에 착수하면 이 목록과 검증 기록을 함께 갱신합니다.

## 저장소 준비 완료

- [x] 프로젝트 이름과 로컬 저장소 위치 결정
- [x] 전체 계획과 첫 기술 결정 정리
- [x] 시작 안내, 환경 점검 절차와 검증 양식 작성
- [x] Git 초기화와 문서·디렉터리 안내의 초기 커밋

## 0 기존 환경 확인

- [ ] Ubuntu 버전·지원 상태, CPU·메모리·디스크 확인
- [ ] 기존 서비스·컨테이너·포트와 데이터 경로 조사
- [ ] SSH 접속 방법과 서버 지문 확인
- [ ] 백업 현황과 별도 백업 위치 결정
- [ ] 기존 DDNS·공인 IP·CGNAT 여부와 HTTPS 선택지 확인
- [ ] 설치 경로·PV 경로·자원 예산·원상 복구 범위 기록

완료 조건: 기존 서비스에 미칠 영향을 설명하고, 보존할 데이터와 새로운 설치 범위를 정할 수 있습니다.

## 1 최소 서비스와 포트폴리오

- [ ] Java·Spring Boot·빌드 도구·Node·Astro 버전 선택과 고정
- [ ] 합성 데이터 schema, seed와 독립적인 기대 결과 정의
- [ ] Spring Boot 샘플 작업·결과 조회 API와 MariaDB 구현
- [ ] 입력 검증·중복·시간·실패 시나리오 확인
- [ ] Astro·React Lab 조회 화면과 API 연결
- [ ] 공개 포트폴리오 저장소와 Pages 주소 확인
- [ ] 소개·경력·프로젝트 설명과 기존 TIL 연결
- [ ] 테스트 결과와 공개 가능한 샘플 결과 기록

완료 조건: 동일 샘플의 기대 결과를 반복 검증할 수 있고, 화면에서 현재 구현 범위와 설계를 이해할 수 있습니다.

## 2 K3s와 CI 및 CD

- [ ] 점검 결과에 맞춰 K3s와 namespace·자원 설정 구성
- [ ] Jenkins controller executor 0과 별도 빌드 agent 구성
- [ ] Java 이미지 빌더 검증, GHCR 게시 권한과 digest 기록
- [ ] devdooly-platform-gitops 저장소와 Helm chart·values 작성
- [ ] Jenkins 테스트·이미지 게시·GitOps 변경 PR 연결
- [ ] Argo CD 동기화와 실제 서비스 버전 확인
- [ ] 정상 배포·실패 차단·이전 digest 복구 검증
- [ ] 재부팅 복구와 필요한 설정·데이터의 외부 백업 확보

완료 조건: 소스 commit부터 image digest, GitOps commit, 실행 버전까지 추적되고 실패·복구 결과가 남습니다.

## 3 외부 공개

- [ ] HTTPS 경로와 관리 도구의 인증된 접근 구성
- [ ] 공개 요약 collector와 허용 필드만 반환하는 API 구현
- [ ] 휴대폰 외부망에서 TLS·화면·API와 관리 접근 제한 확인
- [ ] 검토한 실행·배포 snapshot을 GitHub Pages에 게시
- [ ] Lab 연결 실패 때 상태와 마지막 수집 시각 표시

완료 조건: 방문자가 합성 데이터 결과와 배포 요약을 볼 수 있고, Lab 중단 때도 공개 홈의 프로젝트와 이전 결과를 읽을 수 있습니다. 첫 공개 목표는 여기까지입니다.

## 4 Kafka와 객체 저장소

- [ ] Kafka producer·worker와 멱등 키·재시도·실패 이벤트 보관 구현
- [ ] 중복·역순·중단·재시작 후 결과 건수와 lag 확인
- [ ] S3 후보의 필요한 SDK 기능을 검증한 뒤 제품 선정
- [ ] 결과 파일과 보존 정책, 지연·자원 지표 연결
- [ ] 최대 1,000개 이벤트·전체 동시 작업 1개·요청 빈도 제한 검증
- [ ] 제한을 검증한 뒤 공개 샘플 실행 기능 추가

완료 조건: 입력 건수가 성공·실패·중복·대기로 설명되고, 데이터 유실이나 무제한 실행 없이 결과를 확인할 수 있습니다.

## 5 LLM 개선 사례와 복구

- [ ] 개인 공개 예제로 연산 비효율과 시간 처리 오류 정의
- [ ] AI 제안·사람의 판단·변경 이유·전후 테스트 기록
- [ ] seed·입력 크기·환경·반복 조건을 고정해 측정
- [ ] 별도 테스트 볼륨으로 DB·파일 복원 검증
- [ ] 결과와 한계를 TIL 및 포트폴리오에 연결

완료 조건: 개선 전 실패·개선 후 성공과 측정 원본을 재현할 수 있고, 백업한 데이터의 복원 결과가 있습니다.
