# AI 활용 범위와 검토 상태

이 예제는 2026-10-15 포트폴리오 작업 중 AI coding assistant가 합성 문제, Java 구현, 테스트, JMH harness와 문서 초안을 제안한 공개용 작업입니다. 실제 회사의 수율 계산식, 고객 데이터, 사내 레거시 코드·장애 로그를 재현하거나 옮기지 않았습니다.

| 단계 | 이 작업에서 남기는 근거 |
|---|---|
| 문제 선택 | 구간 합집합·최대 동시 세션이라는 독립 문제와 시간창/입력/오차 제한을 먼저 명시 |
| AI 제안 | 모든 endpoint 구간에서 재검사하는 기준 구현, delta를 모아 sweep하는 개선 구현, UTC offset 손실 오류 예제 |
| 기술적 판단 | 기존 ETL은 이미 O(n)이므로 변경 대상에서 제외. 정렬 비용을 숨기지 않고 O(n log n)으로 표기. UTC 오류 수정과 성능 비교 분리 |
| 검증 | 독립 작은 격자 oracle, 닫힌 형태 fixture, 경계 테스트, JMH 원본 결과·소스/JAR/입력 hash |
| 사람의 검토 | 저장소 소유자의 코드/설계 검토는 별도 단계. 이 문서는 완료된 사람의 승인을 주장하지 않음 |

AI 제안이나 테스트 통과만으로 정확성과 운영 효과가 입증됐다고 표현하지 않습니다. 테스트가 다루는 합성 계약과 JMH가 측정한 제한된 조건을 함께 공개합니다. 실제 측정 전에는 성능 수치를 채우지 않습니다. 사람이 채택·수정·기각한 판단은 해당 PR 리뷰 또는 후속 기록에서 사실대로 추가할 수 있습니다.

이 예제를 이력서에 연결한다면 “AI와 함께 합성 UTC 구간 계산을 분석하고, 독립 oracle·경계 테스트·JMH로 O(n²)→O(n log n) 구현을 검증”과 같이 범위를 밝힐 수 있습니다. 실제 운영 수율 시스템의 개선 수치나 회사 성과로 전환해 서술하지 않습니다.
