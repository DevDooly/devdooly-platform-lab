# 기술 근거의 검색 조건 공유

포트폴리오의 근거 목록에서 검색어·기술·검증 환경을 고른 뒤 **조건 링크 복사**를 누르면 같은 조건을 여는 주소를 복사한다. 지원서나 대화에서 특정 기술의 근거를 바로 안내할 때 사용한다. 링크를 새로 열면 선택한 조건의 처음 6개부터 표시하며, 더 보기로 펼친 개수는 공유하지 않는다.

Clipboard API가 없거나 복사를 거부하면 **공유 주소** 입력을 표시한다. 주소에 초점을 옮기면 전체가 선택되므로 직접 복사할 수 있다. 필터를 변경하거나 조건을 초기화하면 이전 복사 안내와 주소도 지운다. 이전 복사 요청이 뒤늦게 끝나도 새 조건의 안내를 덮어쓰지 않는다. 이미 시작한 브라우저의 복사 작업 자체를 취소하는 기능은 아니다.

링크는 현재 페이지의 HTTP(S) origin·경로와 `evidenceQuery`·`evidenceTopic`·`evidenceScope`, `#evidence`로 구성한다. 기존의 다른 query·hash·userinfo는 포함하지 않는다. 조건 복원은 처음 client 준비 후 수행하며, 서버 검색·자동 주소 변경·새 API 요청·브라우저 저장은 추가하지 않는다. 기존 SSR의 준비 전 비활성·기본 목록은 유지한다.

검색어는 기존 200 UTF-16 상한과 NFKC 검색 순서를 유지한다. 공유 주소 변환에 필요한 URL 문자열 정규화 외에 검색어를 미리 정규화하지 않는다. 알 수 없는 조건 키는 무시하고, 자체 조건 키 중복이나 기술·환경의 잘못된 enum은 전체 조건을 기본값으로 되돌린다. URL은 선택 조건을 전달하며, 근거의 최신성·검증 성공·운영 가용성을 증명하지 않는다.

구현은 `src/lib/evidence-share.ts`·`src/components/EvidenceExplorer.tsx`, 순수 URL 경계 검사는 `tests/evidence-share.test.ts`에서 관리한다. 운영 수집기·이미지 pin·자격증명은 변경하지 않는다.

## 확인한 범위

URL 경계 8개를 포함해 최신 main 통합 후 로컬 웹 검사 259개·생략 0, Astro 50파일 진단 0, 프로젝트 base 지정 단일 빌드 2페이지 성공을 확인했다. 로컬 브라우저에서 공유 조건 복원, 불필요한 query 제거, 중복 조건 초기화, 기존 6→12개 표시를 확인했다.

시스템 클립보드를 읽지 않는 별도 로컬 fixture에서 복사 성공·미지원·거부·지연 완료를 재현했다. 필터 변경 뒤 늦은 완료 안내를 차단하고, 현재 조건의 실패 주소·전체 선택·초기화도 확인했다. 모바일 390px에서 Enter 조작·본문 17px·버튼 48px·문서폭 375px로 가로 넘침이 없었다. 이는 로컬 기능 검증이며 모든 브라우저의 클립보드 권한 동작을 보장하지 않는다.
