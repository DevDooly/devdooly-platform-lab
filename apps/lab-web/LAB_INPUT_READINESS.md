# 실행 결과 화면의 초기 입력 보호

## 확인한 문제

2026-10-23 KST, 빌드 HTML에서 script 요소만 제거한 임시 사본을 로컬 브라우저로 열었습니다. 센서 선택은 활성 상태였고 `all`에서 `sensor-a`로 바꿀 수 있었습니다. native select 값은 바뀌었지만 차트는 두 센서의 선 2개와 포인트 버튼 7개를 그대로 표시했습니다. React의 이벤트가 연결되기 전 입력과 표시 결과가 어긋나는 상태입니다.

실제 느린 통신의 전환 시간을 측정한 시험은 아닙니다. 이 사본은 JavaScript 실행 전 SSR 상태를 재현하며, Git·Pages 배포 출력에는 포함하지 않습니다.

## 변경 범위

실행 결과 화면의 초기 준비 상태를 API 조회 중 상태와 구분합니다. 서버 렌더와 첫 클라이언트 렌더는 같은 준비 전 상태이며, mount 후 화면 조작을 활성화합니다. 준비 중에도 고정 샘플의 수치·차트·출처·문서 링크는 읽을 수 있습니다.

준비 전에는 조회·실행 선택·건수 상세·탭·센서 선택·포인트 선택·이벤트 필터를 비활성화합니다. 준비 후의 센서 필터와 차트 탐색은 네트워크 조회 중 여부와 독립적으로 동작합니다. 실행 선택과 조회 버튼의 기존 로딩 제한은 유지합니다.

API 주소·응답 계약·관측 기록 선택·실패 처리·배포 설정은 바꾸지 않습니다. JavaScript를 실행할 수 없으면 준비 전 상태와 읽을 수 있는 샘플을 유지합니다.

## 검증 기록

- 변경 전 SSR 사본은 센서 선택값만 바뀌고 선 2개·포인트 7개가 남는 불일치를 실제 native 조작으로 재현했습니다.
- 변경 후 SSR 사본에서 `aria-busy=true`, 준비 안내, native 컨트롤 17개 모두 disabled, 센서 `all`·선 2개를 확인했습니다. 임시 사본은 배포 출력 밖에서만 관리했습니다.
- 실제 앱에서는 준비 완료 뒤 `aria-busy=false`와 센서 입력 활성화를 확인했습니다. `sensor-a` 선택 시 선 1개·포인트 4개, `sensor-b`는 선 1개·포인트 3개로 바뀌었습니다. 포인트 선택 시 눌림 상태와 시각·값도 일치했습니다.
- 실패 건수 버튼으로 실패 3행을 표시하고, 전체 필터로 12행을 복원했습니다. 이벤트 탭에서 Home 키를 눌러 차트 탭 선택·초점 이동을 확인했습니다.
- 로컬 API 실패 후 게시 기록을 표시하는 화면에서 위 탐색을 확인했습니다. 이 검증으로 실제 API 연결 성공이나 미니 PC 가용성을 주장하지 않습니다.
- 웹 검사 270개 통과·skip 0, Astro 50파일의 오류·경고·힌트 0, 프로젝트 경로 빌드 2페이지 성공. 390px 화면에서 문서 폭·스크롤 폭 모두 375px이며 센서 조작과 차트를 확인했습니다.
- 다른 세션의 TLS PR221이 반영된 main을 통합한 뒤 웹 273개·skip 0과 2페이지 빌드를 다시 통과했습니다. TLS 변경은 해당 PR의 별도 검증 범위입니다.
