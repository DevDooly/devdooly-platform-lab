# Lab API 오류 응답의 본문 정리

`getJson`이 비정상 HTTP 응답을 받으면 본문을 사용하지 않고 기존의 `HTTP_REJECTED` 진단을 반환한다. 이 경로에서 공유 `discardObservationBody`를 호출해 사용하지 않는 본문의 취소를 요청한다.

취소 완료는 기다리지 않는다. 제공자의 취소가 지연되거나 실패해도 이미 확인한 HTTP 상태를 보존하고, 본문 내용·예외 원문을 공개 진단에 포함하지 않는다. 정상 응답의 JSON 처리와 요청 옵션은 유지한다.

이것은 취소 요청 경계의 보완이다. 실제 소켓 종료·제공자의 정리 완료·상류 수신 바이트 0·성능 개선을 보장하지 않는다. `Promise.all`의 sibling 요청을 join하거나 취소하는 변경도 아니다.

앞서 로컬 HTTP fallback 시험에서 503 대신 `NETWORK_UNVERIFIED`가 나온 두 사례의 직접 원인은 미확정이다. 원본 실패를 보존했고 단독 검사·후속 전체 검사·Linux CI는 통과했다. 이 본문 정리 보완을 그 실패의 원인 규명이나 해결로 표시하지 않는다.

운영 서버의 장애 주입·서비스 재시작·새 토큰·이미지 pin 변경은 수행하지 않는다. Kafka 오류 분류 보완은 다른 변경의 범위다.

## 확인한 범위

원본 코드에서는 취소 요청이 없어 새 세 사례가 실패했고, 최소 수정 후 세 사례와 상위 검사가 통과했다. native Response·ReadableStream에서 앱의 json/text/getReader 호출 0회·취소 요청 1회, 영원히 대기하는 취소 Promise의 비대기, 취소 거절·예외 중 발생한 후속 abort에도 HTTP 상태 보존을 확인했다. 상류 pull·수신 바이트나 연결 종료 검사는 아니다.

다른 세션의 Kafka 수정 main을 통합한 로컬 전체 웹 266개·생략 0, Astro 50파일 진단 0, 프로젝트 base 지정 단일 빌드 2페이지도 성공했다. 새 회귀는 `tests/api-error-body.test.ts`에서 관리한다. 기존 HTTP 시험이나 `Promise.all`은 수정하지 않았다.
