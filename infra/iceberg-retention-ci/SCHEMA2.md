이 문서는 공개 schema 2 진단 계약입니다. 원래 진단 CLI `240851…`는 Linux 62개·skip0을 통과한 두 번째 실행 `38881661893`에서 Class-Path 거부 코드와 prep cold 컨테이너 제거·부재를 기록했습니다. 첫 실행 `38876152951`의 schema 1 원문·Linux 56개 통과·일반 PREP 실패와 원인·정리 미확인은 그대로 보존합니다. Class-Path 코드 다섯 개를 포함한 이전 a03 source는 Linux 67개·skip0을 통과한 뒤 manifest 바이트 guard에서 prep에 실패했습니다. 구체적 분기와 실제 closure·prep·decoder·inventory 성공은 미확인입니다. 이후 a00 source의 네 번째 실행 `38890545126`은 Linux 73개·skip0 뒤 `JAR_MANIFEST_CLASSPATH_TARGET_MISSING`으로 prep에 실패했습니다. 특정 JAR·token·경로와 전체 closure·compile·decoder·inventory 성공은 미확인입니다. 현재 전체 트리·실제 부재 helper와 CLI 코드 여섯 개 추가는 별도 SOURCE_ONLY_NOT_RUN 후보이며 Linux 80개는 미실행입니다. [호환 경계](CLASSPATH_CLOSURE.md)는 공개 필드·PASS 조건·원래 producer·SQL·자원·600초 clock을 바꾸지 않으며, 기본 locked-JAR 거부를 유지한 채 전체 export map 안의 상대 참조만 검증합니다.

기존 공개 필드와 PASS 조건을 유지하고 `schemaVersion`을 2로 바꾸며, 다음 네 키의 `diagnostic`을 항상 추가합니다.

| 키 | 계약 |
| --- | --- |
| `stageAttempted` | CLI의 `PREP`·`COMPOSITE`·`SUMMARY`, 또는 같은 소스의 정확한 composite receipt에서 관측한 고정 `lastStage`. 시도한 단계이며 완료를 뜻하지 않습니다. |
| `failureCode` | 성공이면 null. 실패에서 CLI가 잡은 정확한 `ValueError`의 단일 문자열 인자가 검토된 literal 집합에 있을 때만 그 고정 코드이며, 나머지는 `UNKNOWN`입니다. 임의 uppercase 메시지나 반환된 private composite failureCode는 공개하지 않습니다. |

`lastPrepChild`의 exact 키는 `name`, `class`, `outcome`, `returnCode`, `stdoutBytes`, `stderrBytes`, `timedOut`, `childStarted`, `childReaped`입니다. `childStarted`와 `childReaped`는 해당 소유 명령의 Popen/CLI 프로세스 관측이며 Docker container의 시작·종료를 뜻하지 않습니다. returnCode는 관측되지 않으면 null이고, 두 byte 수는 실제 받아들인 prefix의 크기입니다. 전체 provider 출력을 다 받았거나 EOF를 확인했다는 공개 주장이 아닙니다.

이름은 frozen prep의 16개 label로 제한합니다. class는 `JAVA_VERSION`, `JAVAC_VERSION`, `IMAGE_PULL`, `IMAGE_INSPECT`, `COLD_CREATE`, `COLD_INSPECT`, `CLASSPATH_EXPORT`, `ICEBERG_DOWNLOAD`, `MAIN_COMPILE`, `COLD_REMOVE`, `COLD_ABSENCE`입니다. outcome은 `START_FAILED`, `EXITED_ZERO`, `EXITED_NONZERO`, `TIMED_OUT`, `STDOUT_LIMIT_EXCEEDED`, `STDERR_LIMIT_EXCEEDED`, `OWN_CHILD_REAP_UNVERIFIED`, `OUTPUT_OR_CONTROL_IO_FAILED`, `PRIVATE_OUTPUT_IO_UNVERIFIED`, `PREP_CUTOFF_EXCEEDED`로 제한합니다. 정확한 label 매핑과 검토 코드 literal은 CLI의 고정 상수이며 실행 중 다른 파일에서 목록을 확장하지 않습니다. 이전 manifest `53493f…`는 원래 129개 코드에 한정됩니다. 이전 Class-Path manifest `a9704dce98583b3935e05ac759a3b0e9c8af839fb9b3fa141ad1d96a13708f18`만 원래 129개와 `JAR_MANIFEST_CLASSPATH_TOKEN_REJECTED`, `JAR_MANIFEST_CLASSPATH_REFERENCE_BOUND`, `JAR_MANIFEST_CLASSPATH_EXPORT_MAP_REQUIRED`, `JAR_MANIFEST_CLASSPATH_TARGET_MISSING`, `JAR_MANIFEST_CLASSPATH_CLOSURE_BOUND` 다섯 개를 합한 134개를 허용합니다. 이전 manifest `6aea1d3987d4a258718f4fd242d05ff1364a73cf4772272260975fce7eb172cd`만 이 134개와 `JAR_MANIFEST_DECLARED_EMPTY`, `JAR_MANIFEST_DECLARED_SIZE_BOUND`, `JAR_MANIFEST_READ_MISMATCH`, `JAR_MANIFEST_AGGREGATE_BYTES_BOUND` 네 개를 합한 138개를 허용합니다. 새 manifest `c8a3d89458bca95a98547472816c5fb35f922aea934cd7da1a0cd4534c0c6fbf`만 이전 138개와 `JAR_CLASSPATH_TREE_EXACT`, `JAR_CLASSPATH_ABSENCE_UNVERIFIED`, `JAR_CLASSPATH_TREE_REQUIRED`, `JAR_CLASSPATH_CASE_ALIAS_REJECTED`, `JAR_CLASSPATH_TREE_CHANGED`, `JAR_CLASSPATH_TREE_IO_FAILED` 여섯 개를 합한 144개를 허용합니다. 이전 기록의 허용 코드를 새 목록으로 넓히지 않습니다.
